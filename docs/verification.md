## 再現方法

通常利用は `index.html` を開くだけです。開発用にNode.js 24を用意し、次を実行します。単体テストに追加パッケージは不要です。

```sh
npm run check
npm run benchmark
```

実ブラウザー検証は開発用の追加手順です。[Playwrightの公式手順](https://playwright.dev/docs/library)に沿い、固定バージョンと同梱Chromiumを使います。

```sh
npm install --no-save --ignore-scripts playwright@1.62.1
npx playwright install --with-deps chromium
npm run test:browser
```

`npm start` ではループバックだけに開発用サーバーを開きます。配信対象はHTML、CSS、3つのJavaScriptファイルのみです。ブラウザーテストは一時ポートを使い、テスト終了時にサーバーとブラウザーを閉じます。

## 見つけて修正した問題

- 30,000文字内でも多数の警告の重複除去が重くなるケースがあったため、`Set` と件数上限を導入
- 多数の候補に同じ長い根拠を複製して描画するケースがあったため、候補数と根拠合計量の両方を制限
- 各入力の候補200件・生成メモ200件、差分の根拠合計200,000文字を超えると比較全体を中止。部分結果を表示しない
- 明示年の日付と認識可能な年なし候補が混在すると、後者の年を推測せず確認メモを表示

## 未確認・残る限界

- Chrome/Edge/Firefox/Safariの横断テスト、実端末、file://でのCSP互換性、画面読み上げ、網羅的なアクセシビリティ監査は未確認
- モバイル検証は画面幅の変更であり、物理端末やタッチ入力そのものの検証ではない
- CSP・DOM・通信検査は実行した合成ケースの範囲で、セキュリティ監査や将来の安全性を保証しない
- 固定ルールで、自然言語の意味理解、複雑な否定、年なし日付の推測、PDF/画像/URL取得、曜日変更の意味は扱わない
- 日時のタイムゾーン、イベントの名前・役割の対応付けを推測しない。開始・終了時刻の値だけの交換は差分にならない
- 同じ値はまとめるため出現回数の変化を検出しない。時刻範囲や未対応書式は部分的な認識と警告になる場合がある
- ブラウザーのタブ復元、拡張機能、OSのクリップボード履歴はこのアプリの制御範囲外
- 利用者調査、実際の文書での精度評価、競合との性能比較は未実施
