# お知らせ変更レビュー

大学などのお知らせを手で持ち込み、変更前後の **開催日・時刻・場所・締切・明示された対応事項** を並べて確認する、ブラウザーだけで動く小さなレビュー補助ツールです。差分ごとに、変更前後の原文と行番号を残します。

汎用のテキスト diff ではなく、決めたルールで読めた項目だけを整理します。複数候補を自動で結び付けてしまう場合は、追加・削除と確認メモを表示します。人が原文を見ることを前提にしています。

## 試す

1. index.html を Chrome、Edge、Firefox などのブラウザーで開きます。
2. **合成デモを読み込む** を押します。
3. **変更を確認** を押します。
4. 各項目の変更前後、根拠にした行、確認メモを見ます。

ローカルでテストするには Node.js の標準テストランナーを使います。

~~~~powershell
node --test tests/*.test.js
~~~~

通常利用・Node.jsの単体テストには、ビルド、アカウント、パッケージのインストール、課金 API は不要です。入力を保存する機能もありません。実ブラウザーの開発用検証に限り、固定バージョンのPlaywrightとChromiumを使います。

## できること

- 項目名のある開催日と締切を、明示年の日付にそろえて比較します（例: 2026年10月24日、2026/10/24）。
- 項目名のある時刻（例: 時間：13:30、午後1時30分）を比較します。締切の日付と時刻が同じ項目に1つずつ明記されている場合は、締切を「2026-10-20 17:00」のように比較します。
- 場所、会場、実施場所、集合場所、教室で始まる場所行を比較します。
- 「提出してください」「登録が必要」など、明示的な指示表現の対応事項を比較します。
- 変更前後の各結果に原文の抜粋と行番号を添えます。
- 同じ文面の項目を差分から除き、日付形式の異常や複数候補を確認メモに出します。

## プライバシーの設計

- 入力は画面上でだけ扱います。ネットワーク API、分析サービス、外部フォント、Cookie、Local Storage、IndexedDB は使っていません。
- 大学ポータル、学内メール、URLへの接続、スクレイピングは実装していません。
- デモは架空のイベント名、日付、場所だけです。実在の個人情報や大学のお知らせは含みません。
- 結果の文字列は DOM の textContent で表示します。HTMLとして実行しません。
- オフラインで index.html を開いて使えます。このアプリは入力を永続保存しません。ただし、ブラウザー自身のタブ復元・拡張機能・OSのクリップボード履歴などは制御できません。

この説明はこのリポジトリの実装についてです。入力には、最初は付属の合成デモを使ってください。コード変更後に公開する場合も、ネットワーク送信や保存を追加していないことを再確認してください。

## 限界

- 日本語の平文と決めたラベル・表現だけを扱うルールベースの試作です。文書全体の意味、暗黙の依頼、言い換え、文脈、変更の見落としを判定しません。
- 年のない日付、和暦、曜日だけの変更、PDF・画像・添付ファイル・Webページは解析しません。文章を手でコピーできる形にして使ってください。
- 「申込期限：日付」のようなラベル付き日付や、「○○までに回答してください」のような明確な期限文が対象です。複数の期限や場所がある場合、文意で正しく対応付けられるとは限りません。
- 対応事項は語尾を含む明示的な表現を拾うため、組織固有の言い回しや、婉曲な指示は見落とすことがあります。否定表現も限られた語句だけで判定します。
- 1つの文面は30,000文字（JavaScriptのUTF-16コード単位）までです。長文は項目ごとに分けてください。入力を編集・入れ替えたときは、古い結果を消して再比較を促します。
- 通知、カレンダー同期、履歴、ファイル取り込み、編集可能なルール設定はありません。
- 同じ値の重複はまとめます。出現回数の変化や、同じ日付を持つ別イベントの入れ替えは検出できない場合があります。開始時刻・終了時刻も同じ「時刻」の値集合として比較するため、13:00と14:00の役割だけを入れ替えた変更は検出しません。タイムゾーンも推測しません。
- 入力文字数に加え、各文面の重複を除く抽出候補200件・生成する確認メモ200件・差分に添える根拠の合計200,000文字に上限があります。超過時は比較全体を中止し、部分結果を表示せず、入力の分割を促します。長い原文を大量の結果カードへ繰り返すことによる画面停止を防ぐためです。
- 年なしの日付は推測しません。明示年のある日付と「10/21」「10月21日」などが混在すると確認メモを出しますが、すべての未対応表現を警告できるわけではありません。「13:30-14:00」のような時刻範囲も一部を未対応として警告することがあります。
- 正式な案内の根拠や最終判断には使わず、原文を確認してください。
- 利用者の需要はまだ検証していません。顧客連絡や課金設定も行っていません。

## 技術とテスト

検証範囲と未検証の範囲は [検証記録](docs/verification.md) を参照してください。

- HTML / CSS / JavaScript（ブラウザー標準 API のみ）
- 日付の暦日妥当性、全角数字と時刻の正規化、場所・必須対応の差分、複数候補の警告、合成デモを Node.js の組み込みテストで確認します。
- 実装判断と候補比較は [設計判断](docs/design-decisions.md) と [関連ツールとの比較](docs/product-comparison.md)、面接前の準備は [面接準備](docs/interview-prep.md) を参照してください。
- 合成デモと期待結果は demo/ にあります。
- 開発用の再現手順、ブラウザーテスト範囲、計測環境は [検証記録](docs/verification.md) にあります。CIは読み取り専用権限で合成データのみを扱い、デスクトップ・狭い画面幅のスクリーンショットを7日間保存します。

## 調査した関連プロジェクト

- [Diffchecker](https://www.diffchecker.com/) はテキストなどの汎用差分を見比べるサービスを提供し、デスクトップ版はオフライン比較を案内しています。この作品はオフライン性そのものを新規性として主張せず、日本語のお知らせで項目を絞り、行番号つき根拠を並べる範囲に取り組みます。
- [changedetection.io](https://github.com/dgtlmoon/changedetection.io) はWebページの変更を継続監視して通知するオープンソースプロジェクトです。READMEにはAIによる変更要約・条件設定の説明もあります。この作品はWebを監視せず、貼り付けた2つの文面だけを比較します。

どちらのコードや画像も取り込んでいません。ライセンス条件を引き継ぐコード・素材はありません。

## AI支援の制作過程

この初版はAI支援で調査、設計、実装、テスト、文章作成を行いました。ソース・素材の流用はしていません。リポジトリの持ち主は公開や応募の前に、ルールの根拠、誤判定の限界、テスト内容を読み、自分の言葉で説明できることを確認してください。練習質問と説明の軸は [面接準備](docs/interview-prep.md) にまとめています。
